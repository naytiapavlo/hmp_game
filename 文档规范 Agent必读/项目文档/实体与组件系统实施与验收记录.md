# 实体与组件系统实施与验收记录

日期：2026-09-23  
工程：`HMP_game`，Unity `6000.6.0f1`。  
依据：《实体与组件系统建设计划》《关卡系统重构前耦合与复用分析》。

## 1. 交付范围

本次实现轻量实体系统和办公室迁移试点。核心程序集 `HMProtection.Entities` 只依赖 Unity 与基础运行库；引用旧玩法脚本的适配器留在默认程序集中。

| 层次 | 已实现内容 |
|---|---|
| 身份与查询 | `EntityId`、包含 Scope/ID/代次的 `EntityHandle`、多标签排序快照、注册/注销、失效检查 |
| 生命周期 | 明确的内容根、含 inactive 的收集、事务安装、失败回滚、逆序 Detach、重入拒绝、Scope 释放 |
| 能力 | 显式能力清单、接口索引、Attach/Prepare/Detach、Anchor、Fire、Interaction |
| 激活 | `EntityFacade.TrySetActive/TryGetActive`；区分 activeSelf 与 activeInHierarchy，不主动激活祖先 |
| 绑定与命中 | 角色到实体 ID 的绑定、能力与槽位校验、Collider 到实体的显式代理 |
| 办公室接入 | 玩家、出生点、主火源、四个交互目标、原 SceneChoiceAnchor 的兼容映射 |
| 停止与重开 | 停止取消问题/反馈/路线并释放 Scope；试点重开采用场景重载 |
| 编辑器 | 独立试点装配、按 Scope 校验、Inspector 入口、只读实体与错误诊断列表 |

初始安装顺序：收集和静态验证 → 临时身份/能力索引 → 角色和命中绑定验证 → 全体 Attach → 全体 Prepare → Ready → Registered。初始化期间，能力只能通过传入的 Context 解析依赖；对外 Registry 查询在 Ready 前拒绝访问。

激活能力首版直接由 Facade 操作 `GameEntity.activationTarget`，没有另外增加 `IEntityActivation` 组件。错误采用 `EntityError`；旧玩法适配器的命令返回 `bool + error`。这两项是计划接口草案的具体落地选择。

## 2. 试点对象和边界

场景：`Assets/Scenes/办公室场景-实体试点.unity`。正式办公室场景、关卡注册表和 Build Settings 保持原配置，试点可以直接在编辑器打开运行。以后若用于构建，需要显式加入构建场景并配置相应关卡入口。

| 实体 ID | 作用 |
|---|---|
| `player.main` | 显式玩家角色绑定 |
| `anchor.player.spawn` | 出生位置 `origin` 槽位 |
| `fire.office.main` | 主火源 `fire` 能力与 `origin` 锚点 |
| `target.office.printer` | 打印机交互与 approach 锚点 |
| `target.office.window` | 窗户交互与 approach 锚点 |
| `target.office.entrance` | 入口交互与 approach 锚点 |
| `target.office.power_strip` | 插排交互与 approach 锚点 |
| `anchor.scene_choice.*` | 原气泡 anchorId 对应的稳定实体 |

`OfficeEntityBindings` 是过渡装配边界。启用时，Flow、Presenter、Interactor 和 Bootstrapper 必须一起接入；绑定缺失时终止准备，不回退到全局 Find。未启用时，原场景继续使用既有路径。命中已托管 Collider 后若实体不可用，交互链路拒绝操作，不再次走旧交互执行同一动作。

## 3. 验证方法与结果

验证在工程内 `Temp/EntityValidationProject` 的独立副本运行，没有关闭用户已经打开的 Unity，也没有覆盖原有未提交的模型、材质、第三场景或 VFX 改动。

| 验证项 | 结果 |
|---|---|
| 实际 Unity 编译：核心、旧脚本适配、Editor 与测试程序集 | 通过 |
| EditMode 核心测试 | **20 / 20 通过** |
| PlayMode 生命周期测试 | **4 / 4 通过** |
| 独立试点创建 | 通过 |
| 同一试点重复安装及完整只读校验 | 通过 |
| 办公室三题、真实 E 交互、结算、十次重开、停止 | **通过** |

EditMode 覆盖：Scope 隔离、重复 ID、inactive、激活祖先行为、代次失效、动态失败回滚、初始坏绑定无副作用、Ready 发布时机、安装期解析、能力所有权、异常回滚、重入、逆序释放、重复 Collider 拒绝等。

PlayMode 覆盖：已激活实体销毁、动态 inactive 注册/启用/注销/销毁、初始 inactive 实体直接销毁、内容场景卸载导致 Scope 释放。

集成脚本 `EntityIntegrationChecks` 使用 Input System 的测试键盘发送 E，先验证物理射线命中真实 `OfficeChoiceTarget` 及 Registry 映射；没有直接调用交互适配器替代输入。导航点不是交互站位：插排导航点到目标约 3.7 米，超过原交互距离 2.8 米，因此脚本通过 `CharacterController.Move` 在碰撞约束下靠近后再交互，未扩大射程或修改 Collider。

### 集成记录

最终集成结果为 **PASS**：必需 ID/角色/锚点解析、对象改名与换父级、两个动态火源状态隔离、三题 E 交互与正确计分、反馈讲解和结算、十次真实场景重载后的旧句柄失效/四目标重建/计分归零，以及 StopLevel 释放 Scope 均通过。

原始记录保存在同目录 `验证记录/实体系统/`：`entity-edit-tests.xml`、`entity-play-tests.xml`、`office-integration.txt`。复制回主工程的试点与测试使用相同脚本及 GUID。

运行日志中出现 Unity Editor 自身 `UnityEditor.Search.SearchDatabase` 启动索引异常；未发生在实体或玩法调用栈，未阻断测试。该环境日志不等于实体系统功能失败，也不将整份 Editor 日志宣称为无错误。原工程已有的 obsolete API 与 StageTimer 未使用事件警告仍保留。

因此，本轮交付可用于继续试点制作与验证；在上述回归补齐前，不把 P5 的全部完成标准或正式场景全面切换视为已验收。
