## 四、工程约定（新人必守）

1. **场景装配工具模式**：场景内容不手摆——`Assets/Editor/` 下每个 `*Setup.cs` 都是 `[InitializeOnLoad]` 自动装配器（按场景 marker `Library/<名>.<场景名>.done` 防重跑，菜单 `Tools/<分类>/Re-run ...` 强制重跑，报告写 `Library/*.json`）。改动配置后删对应 marker 或走菜单。
2. **脚本默认值陷阱**：已挂场景组件不吃代码新默认值（序列化优先）——需要刷值时在对应 Setup 里用 SerializedObject 强写（先例：InteractionSetup 刷 followFactor）。
3. **Unity 命名查找**：场景根按中文名（`场景`/`人物`/`body`）；骨骼/网格按 `SM_`/`Index.01.L` 等命名约定。
4. **git**：推送需走本地代理 `git -c http.proxy=http://127.0.0.1:7897 push`；LFS 已覆盖 `*.blend *.fbx *.psd *.mp4 *.mov *.webm`（PNG 按项目惯例普通 git）；`.codex-artifacts/` 已忽略（火焰模拟缓存在此，配合 `模型/火焰制作/` 的脚本可复现烘焙）。
5. **多 Agent 协作**：合作者（GPT）会直接提交/写文件，动手前先 `git fetch` 查新提交；其 UI/CG 代码改数据源时保持其视觉 prefab 与接口不动。
6. **运行时调试键**：F8=路线指引准星选点（GuidanceSystem.debugMode）；F9=火焰四级循环（FireEffectController.debugMode）；E=交互/轻放、Q=丢弃。

## 五、已踩过的坑（历史教训，勿重蹈）

1. `body` 缩放非均匀 (0.5,1,0.5)——**在它下面旋转任何子物体都会被剪切变形**；旋转类组件挂「人物」根下的均匀缩放支点（先例：ArmsPitchFollow 运行时建 ArmsPivot）。
2. Rigidbody 插值会冻结 kinematic 持物的 Transform——持物期间 `interpolation=None`，放下恢复。
3. 跨组件查找若依赖会被别人改动的层级，解析必须放 `Start()`（Awake 顺序竞速；先例：Interactor 找 HandPoseController）。
4. Editor 安装器等待资产就绪必须用 `LoadAssetAtPath` 判真 + `isUpdating`，`FindAssets` 按名字会抢跑（先例：FireVisualUpgrade 导入竞速）。
5. 办公室 FBX 有巨型外壳/楼板碰撞体（AABB 封死 97% 栅格）与 -90° 根旋转——寻路障碍须过高度带+面积过滤。
6. 场景 YAML 冲突解法：取协作者版本 + 装配工具重跑重建我方内容（IDempotent 是硬要求）。
