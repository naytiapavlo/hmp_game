# 关卡数据与游戏逻辑分离——架构设计（骨架版）

> 状态：**骨架与选关接入均已实施**（2026-09-20 定稿 → 2026-09-22 §五 选关数据驱动落地，见《第二关（灭火器扑救）接入说明.md》）
> 决策记录：实施范围 = 架构骨架 + 选关接入；配置载体 = **JSON**；选关界面 = **读关卡列表自动生成卡片**。
> 实施启动时以本文档为准；本文档不涉及已实施内容，仅设计。

---

## 一、目标

1. **加关卡零逻辑代码**：新增关卡 = 做场景 + 写一份 JSON + 注册表加一行，选关界面自动出现新卡片；
2. **游戏内切关零改动**：重开本关 / 下一关 / 返回主菜单走统一 API，结算 UI 直接调用；
3. 每关自带**路线指引系统**的数据定义（渲染引擎后续阶段实现）；
4. 兼容现有资产：交互框架、CG 转场、主菜单 UI、按场景自动装配的 Editor 工具链全部复用。

## 二、三层架构

```
┌─ 关卡内容层（每关一份，加关卡只动这层）────────────────┐
│ JSON 配置：Assets/Resources/Configs/                     │
│   ├─ levels.json              关卡注册表（列表/顺序/解锁）│
│   └─ Levels/level_xxx.json    每关配置（出生点/阶段/题库/ │
│                              指引路线/计分，骨架先留字段） │
│ 场景内容：关卡场景 + LevelBootstrapper（场景适配器）      │
├─ 逻辑层（通用引擎，不随关卡变化）──────────────────────┤
│ scripts/关卡/：LevelCatalog（读注册表）                  │
│   LevelManager（加载/切换/重开/返回菜单，DontDestroyOnLoad）│
│   LevelBootstrapper（场景锚点适配：出生点/相机/起火点）   │
│   ConfigLoader + LevelDto（JSON 反序列化）               │
├─ 表现层（复用现有）────────────────────────────────────┤
│ SceneSelectUI（改读关卡列表自动生成卡片）                │
│ CgTransitionPlayer（CG 转场，经适配器接入 LevelManager） │
└─────────────────────────────────────────────────────────┘
```

**加一个新关卡的三步**：
1. 做关卡场景，放一个 `LevelBootstrapper`（含锚点子物体）；
2. 写 `Resources/Configs/Levels/level_xxx.json`；
3. `levels.json` 的 levels 数组加一条 → 选关界面自动出现新卡片。

**直接 Play 关卡场景**（开发调试常用）也走 `LevelBootstrapper` 的默认关卡配置，行为与从主菜单进入一致。

## 三、JSON 数据结构（JsonUtility DTO）

### 3.1 注册表 `Resources/Configs/levels.json`

```json
{
  "levels": [
    {
      "id": "level_1_initial_fire",
      "displayName": "初起火灾应对",
      "sceneName": "办公室场景",
      "configPath": "Configs/Levels/level_1_initial_fire",
      "status": "available",
      "unlockAfter": "",
      "order": 1,
      "transitionVideo": "起火"
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| id | 关卡唯一标识（内部引用/解锁依赖/存档记录用） |
| sceneName | 目标场景名（SceneManager 按名加载） |
| configPath | 该关 JSON 在 Resources 下的路径（不含扩展名） |
| status | `available` / `locked` / `comingSoon`（选关卡片三态） |
| unlockAfter | 锁定态的解锁条件：另一关的 id（通关后解锁）；空 = 不依赖 |
| order | 卡片排序 |
| transitionVideo | 进关 CG 转场视频名（对应 Assets/CG 下的 mp4，空 = 无 CG 直接进） |

### 3.2 单关配置 `Resources/Configs/Levels/level_1_initial_fire.json`

```json
{
  "id": "level_1_initial_fire",
  "displayName": "初起火灾应对",
  "description": "办公区插排过载引发初起火灾，学习报警、断电与扑救判断。",
  "spawnPoint": "LevelBootstrapper/锚点_出生点",
  "stages": [],
  "quiz": null,
  "guidanceRoutes": [],
  "fireCues": []
}
```

- **场景内物体一律按「名字路径」引用**（如 `LevelBootstrapper/锚点_出生点`）——项目命名规范强、InteractionSetup 已验证该模式，天然规避 JSON 无法引用 Unity 资产的问题；
- `stages / quiz / guidanceRoutes / fireCues` 骨架阶段只定义 DTO 空壳结构，引擎后续阶段实现：
  - `stages`：状态机阶段序列（CG动画/俯视答题/自由取物/结果动画/科普视频/结算…每段含时长、是否计时、分值权重）；
  - `quiz`：题库（题干/选项/正确答案/解说/每题指引目标映射/每题时长）；
  - `guidanceRoutes`：指引路线（路线 id、路径点名字列表、样式=地面箭头/标签气泡、`visibleDuringPlay` 开关——第三关逃生路线为考核内容，设 false 防剧透）；
  - `fireCues`：火势提示（阶段 → 火势等级 0-1/规模/烟量，交给 FireEffectController）。

### 3.3 为什么 JSON 放 Resources

运行时 `Resources.Load<TextAsset>` 直接可读，无需 Addressables / StreamingAssets 搬运；配置体量小，全量打进包无负担。计划书第七章写的是 `Assets/Configs/Level1/` 的"asset 或 json"，此处为可运行性选择 JSON+Resources 路径，字段口径不变。

## 四、类职责（新增文件清单）

| 文件 | 命名空间 | 职责 |
|---|---|---|
| `scripts/关卡/LevelDto.cs` | HMProtection.Core | [Serializable] DTO：LevelEntry / LevelConfig / StageConfig / QuizData / GuidanceRouteDto 等空壳 |
| `scripts/关卡/ConfigLoader.cs` | HMProtection.Core | 读 levels.json 与单关 json；缺字段、缺场景、JSON 语法错误在 Console 给明确报错 |
| `scripts/关卡/LevelCatalog.cs` | HMProtection.Core | 解析注册表：按 id 查询、按 order 排序、结合通关记录计算锁定态（骨架期按数据呈现） |
| `scripts/关卡/LevelManager.cs` | HMProtection.Core | `Ensure()` 懒创建（DontDestroyOnLoad）；`StartLevel(id, transition)`：LoadSceneAsync → 等 ILevelTransition.Done → allowSceneActivation → 找 LevelBootstrapper 握手 → 就绪事件；`RestartLevel / LoadNext / ReturnToMenu` |
| `scripts/关卡/ILevelTransition.cs` | HMProtection.Core | 转场接口 Begin/Done/Cancel；给现有 CgTransitionPlayer 写薄适配器，CG 逻辑零改动 |
| `scripts/关卡/LevelBootstrapper.cs` | HMProtection.Core | 场景适配器：每关场景一个；持有默认关卡 id（直开场景兜底）；锚点子物体按 JSON 名字路径解析；`PrepareLevel(config)` 定位玩家、暴露场景侧能力（俯视相机/起火点/天花板显隐桥接等后续阶段接入） |
| `Editor/LevelSetup.cs` | — | 按项目 InitializeOnLoad + Library marker 模式，给办公室场景装配 LevelBootstrapper 并生成锚点子物体（出生点取当前玩家位） |

## 七、验收标准（骨架轮）

1. 初始界面 Play：选关卡片由 levels.json 生成（1 张可用；加 locked/comingSoon 条目能正确显示对应态）；
2. 选「初起火灾应对」→ 开始：CG 转场照常 → 进办公室场景，Console 打印关卡就绪日志（配置加载成功、玩家定位到出生点）；
3. 直接 Play 办公室场景：走 bootstrapper 默认关卡，无报错；
4. 交互框架、CG、主菜单其余功能回归正常；
5. 加关演示：往 levels.json 塞一条假关卡（同场景）→ 重进 Play 卡片自动多一张，全程零代码改动。
