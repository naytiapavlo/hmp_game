## 一、目标与硬性接口

1. **核心接口由需求方指定**：路线生成的入参就是「目的地坐标 + 当前场景的障碍物信息」——

   ```csharp
   // 障碍物信息抽象（场景适配层各场景自行实现）
   public interface IObstacleProvider
   {
       // 用障碍数据构建占用栅格（cellSize 网格边长，area 规划区域）
       OccupancyGrid BuildGrid(float cellSize, Bounds area);
       // 数据失效通知（门开合、家具被移动等动态变化时由实现方触发）
       event Action ObstaclesChanged;
   }

   // 规划器：纯函数、无场景依赖，任何场景复用同一份代码
   public static class RoutePlanner
   {
       // 返回是否成功；waypoints 为平滑后的地面路径点（含起终点）
       public static bool TryPlanPath(Vector3 start, Vector3 destination,
                                      OccupancyGrid grid, out Vector3[] waypoints);
   }
   ```

2. **换场景零改动**：新关卡场景只需提供自己的 `IObstacleProvider` 数据（默认实现从场景静态碰撞体自动收集），规划器与渲染器全部复用；
3. 游戏内表现：玩家脚下 → 目的地之间的地板上显示高亮指引路线；目的地显示「向下箭头 + 目的地名称」。

## 二、分层结构

```
┌─ 门面层 ────────────────────────────────────────────────┐
│ GuidanceSystem（MonoBehaviour，每场景一个，装配工具自动挂） │
│   ShowRoute(Vector3 dest, string label)  显示/换路线      │
│   HideRoute()                            隐藏             │
│   （对关卡层与 UI 层的唯一入口；负责跟随重算节流）          │
├─ 规划层（纯逻辑，可单测，无 MonoBehaviour）──────────────┤
│ RoutePlanner   A* 寻路 + LOS 路径平滑                    │
│ OccupancyGrid  占用栅格数据结构（XZ 平面，cell 0.25m）    │
├─ 场景适配层（换场景只换这层的数据）──────────────────────┤
│ SceneObstacleScanner : IObstacleProvider                │
│   从「场景」根收集静态碰撞体 → XZ 投影栅格（缓存+失效）    │
├─ 表现层 ────────────────────────────────────────────────┐
│ FloorArrowRenderer   地面三角箭头带（动态合并 Mesh）      │
│ DestinationMarker    悬浮倒三角 + 名称文字               │
└──────────────────────────────────────────────────────────┘
```

## 三、规划层设计（核心算法）

### 3.1 为什么选自研栅格 A*，不用 Unity NavMesh

- 接口契约要求「障碍信息作为**输入参数**」——NavMesh 的数据流方向相反（编辑期烘焙、场景自带，规划器不接收障碍参数）；
- 办公室场景 765 个**非凸** MeshCollider 走 NavMesh 需要逐物体加静态标记 + 烘焙管线，与现有「按名字约定自动装配」的工具链模式冲突；
- 栅格法运行时构建、输入即数据、`RoutePlanner` 可脱离场景做 EditMode 单元测试；
- 性能余量充足（见 3.4）。NavMesh（包已在依赖中：`com.unity.ai.navigation 2.0.14`）作为备选方案保留，若未来出现多层立体寻路需求再评估。

### 3.2 障碍收集（SceneObstacleScanner）

- 扫描「场景」根下所有 **Collider**，投影为 XZ 平面矩形进入栅格；
- **高度过滤（关键）**：只取包围盒与玩家行进高度带 `[0.1m, 1.8m]` 相交的碰撞体——天花板（≈2.7m）与地面装饰若不过滤会把整张图封死；
- **排除清单**：门板/把手（DoorController 的旋转部件）、可抓取物（PickupItem，会被拿走）、玩家胶囊与 FPHands（不在「场景」根下，天然不扫）；
- 输出：`OccupancyGrid`（cell 0.25m），整图缓存；`ObstaclesChanged` 触发重建（门开合等，v2 再接）。

### 3.3 寻路与平滑

- **A\***：8 邻域、**禁止对角穿角**（斜向移动要求两个相邻直行格均空闲）、代价 = 距离、启发 = 欧氏；
- **LOS 平滑**：Bresenham 格线可视性检测，把 A* 的折线合并为最少路点（转角保留），消除网格锯齿；
- 目的地/起点落在障碍格（如贴墙的灭火器箱）时：在周围 0.5m 半径螺旋搜索最近空闲格，防止"目标不可达"假失败；
- 找不到路（真被围死）→ 返回 false，由门面层处理（v1 表现为直线箭头指向目标 + 警告日志，不阻断玩法）。

### 3.4 性能预算

办公室约 50m×40m → 0.25m 格 = 200×160 = 3.2 万格，A* 单次毫秒级；栅格构建（765 碰撞体投影）<10ms，进关时做一次并缓存。玩家**跟随重算**：偏离当前路径 >0.6m 或目的地移动时触发，节流 0.5s——实际每秒最多 2 次规划，无感知开销。

## 四、表现层设计（视觉规格按参考图）

参考图（`0c7a3b35…png`）解析结论：地面为**等距发光白色三角箭头序列**指向前进方向，非连续条带；目的地为**悬浮发光倒三角 + 上方白色发光名称文字**；整体纯白自发光 + Bloom 辉光，与冷灰办公环境形成对比。

### 4.1 地面箭头带（FloorArrowRenderer）

- 沿平滑路径**等距铺设发光三角箭头**（间距 ≈ 箭头长度，第一个箭头在玩家脚下）——非连续条带，与参考图一致；
- 箭头 = 程序化三角面片，朝向 = 路径切线方向，**所有箭头合并为一个动态 Mesh（1 Draw Call）**，每次重算路径重建顶点；
- 贴地：每段路径向下 Raycast 取地面高度 + 抬升 0.03m 防 Z-fighting；
- 尺寸：箭头宽约 0.5-0.8m（约走廊 1/4 宽），Inspector 可调；
- 材质：URP Unlit 自发光白 + 边缘辉光（Bloom 走场景后处理），**流动动画**：沿路径方向的透明度/亮度脉动（shader 时间参数，约 0.5-1s/格）；
- 材质与 shader 是独立资产（`Assets/Guidance/MAT_GuidanceArrow.mat`），**后续可整颗交给 Astra 替换升级视觉**，代码不动。

### 4.2 目的地标记（DestinationMarker）

- 悬浮**发光倒三角**（尖朝下），高度 = 目标点上方 2.3m，缓慢上下浮动动画；
- 倒三角上方**名称文字**：TextMeshPro 世界空间版（项目已引入 TMP），白色发光、无衬线小写字体、无背板（发光对比保证可读）；文字 Billboard 始终面向玩家；
- 到达检测：玩家水平距离 < 1.2m → 门面层触发 `OnDestinationReached` 事件（关卡层据此推进状态，如第一关"取到物品判定成功"）。

## 五、与关卡架构的衔接

- 关卡 JSON 的 `guidanceRoutes`（见《关卡架构设计（骨架版）》3.2 节）定义：路线 id、**目的地的场景名字路径**（解析为 Transform → 世界坐标）、显示名、`visibleDuringPlay`；
- 第一关流程：答题选择 → 关卡层查映射（如"使用灭火器"→"灭火器箱"）→ `GuidanceSystem.ShowRoute(目的地坐标, "灭火器箱")`；
- 第三关逃生路线 `visibleDuringPlay:false`：路线是考核内容，通关结算时才由关卡层调 `ShowRoute` 做回放展示——**策略在关卡层，本系统只提供显隐 API**；
- 装配：`Editor/GuidanceSetup.cs` 按项目 InitializeOnLoad + marker 模式给每个关卡场景挂 GuidanceSystem（含 SceneObstacleScanner 引用），与 InteractionSetup/LevelSetup 同套约定。

## 七、实施步骤（单独一轮可完成）

1. `IObstacleProvider + OccupancyGrid + RoutePlanner`（纯逻辑三件套，先写 EditMode 测试：假想栅格上的绕障/穿角/不可达用例）；
2. `SceneObstacleScanner`（办公室实测：投影数量、高度过滤、排除清单）；
3. `FloorArrowRenderer + DestinationMarker`（先用程序化材质，Bloom 辉光依赖场景后处理，无则纯白也成立）；
4. `GuidanceSystem` 门面 + 跟随重算 + 到达事件；
5. `GuidanceSetup` 装配 + 开发期调试挂点（准星指向处生成路线的 Debug 快捷键，便于全屋巡检）；
6. Unity 验证（见第八节）→ 材质规格整理一段交给 Astra（可选升级项）。

## 八、验收标准

1. 办公室场景任意可达点：脚下→目的地的地面出现等距发光箭头带，遇桌椅**绕行**而非穿模/穿墙；
2. 目的地有悬浮倒三角 + 名称文字，文字始终面向玩家；
3. 玩家偏离路线 >0.6m 自动重算，改走新路后箭头跟着变；
4. 到达目的地 1.2m 内触发到达事件（Console 可见）；换目标（ShowRoute 新目的地）无缝切换；
5. 性能：规划 <5ms/次、箭头渲染 1 Draw Call、1080p 帧率无感知变化；
6. 复用性演示：不动规划/渲染代码，仅靠 IObstacleProvider 在另一个场景出路线。

## 九、风险与预留

1. **门槛/地毯高差**：栅格只看 XZ 占用，0.03-0.05m 高差会被当可通行——正确（玩家 CharacterController stepOffset 0.3m 可跨）；若有真实不可通行高差场景，v2 给 OccupancyGrid 加高度层；
2. **动态障碍**（门、被推动的椅子）：v1 静态快照 + 手动失效接口；v2 门开合事件接入 `ObstaclesChanged`；
3. **多段路线**（途经点）：接口预留 `ShowRoute(IReadOnlyList<Vector3>)` 重载，规划器逐段调用拼接；
4. **箭头与地面材质冲突**（透明/反光地板）：抬升高度与材质混合模式预留 Inspector 逃生口；
5. **TMP 中文字集**：目的地名称可能含中文，实施时检查 `TMP Settings` 默认字体字集，缺字让 Astra 出字体或用 legacy Text 兜底。
