# 通用玩法组件接入与实施记录

本文记录“通用玩法组件与关卡服务集成计划”的当前代码落点和接入方式，供新增关卡、场景试点和后续迁移使用。本文以实际代码和 Unity 验收记录为准；原计划中的进一步迁移及人工验收不自动视为完成。

## 1. 当前分层

```text
EntitySystem          实体身份、能力注册、碰撞命中映射、角色绑定
LevelSession          一次关卡运行的时钟、计时、事件、控制权和停止边界
GameModules           与关卡内容无关的火焰、交互、题目、计分、表现、可见性契约
EntityAdapters        Unity 旧组件与上述契约之间的显式适配
LevelDefinition       场景选择的内容入口；决定是否运行旧阶段流程
```

`EntityScope` 仍只负责实体基础设施。火焰、门、座椅、拾取、题目与计分不写进 EntitySystem 核心，而由 GameModules 的接口和 Adapter 组合进入一个 Scope。关卡自身的题目顺序、答案、讲解和结算仍属于关卡内容。

## 2. 运行基础：Core 与 Sessions

实体核心位于 `HMP_game/Assets/Framework/EntitySystem/Runtime/`，程序集为 `HMProtection.Entities`。场景通过 `GameEntity` 声明稳定 ID、标签、能力和激活目标；`EntityScopeHost.Configure(...)` 提供内容根、`SceneBindingSet` 和 `EntityHitProxy` 后，再由 `TryInitialize(levelId, out error)` 事务式安装。运行代码应使用 `EntityHandle` 访问，不应以对象名或全局查找替代实体 ID。

会话基础位于 `HMP_game/Assets/Framework/LevelSession/`，程序集为 `HMProtection.Sessions`：

| 文件 | 责任与主要 API |
|---|---|
| `LevelSession.cs` | `LevelSession(EntityScope)` 聚合一次运行；`Start` 要求 Scope 已 ready；`Tick(simulationDelta, presentationDelta, out error)` 推进服务；`Stop`/`Dispose` 取消生命周期、释放服务及实体。`ControlMask.Simulation` 被占用时，本 Tick 的 simulation delta 会归零。 |
| `ScopeEventBus.cs` | 会话内强类型 FIFO 事件；`Subscribe<T>(Action<T>)` 返回可释放订阅，`Publish<T>` 入队，`Dispatch(maxEvents)` 有单次派发上限且监听异常彼此隔离。待派发队列也有限制，超量事件会被丢弃并记录警告。 |
| `ClockAndTimers.cs` | `LevelClock` 保存 simulation/presentation 时间；`SessionTimerService.Start(duration, ClockDomain, callback, ...)` 创建代次句柄，支持 `Cancel`、`Restart`、`Pause`、`Resume`、`TryGetRemaining` 和显式 `Tick`。超时或取消后旧句柄不能复用。 |
| `ControlLeaseService.cs` | `ControlLeaseService.Acquire(owner, ControlMask)` 返回 `IDisposable` 租约；`IsBlocked(mask)` 合并所有未释放租约。掩码包括 Simulation、Movement、Look、Interaction、ToolUse。 |

Unity 侧由 `HMP_game/Assets/GameContent/Common/EntityAdapters/LevelSessionHost.cs` 承接。`Bind(EntityScope, out error)` 创建并启动 Session；其 `Update` 调 `Session.Tick(Time.deltaTime, Time.unscaledDeltaTime, ...)`；`Acquire(owner, mask)` 提供租约；`Release()` 先通知 `Stopping`，再释放 Session。不要让多个 MonoBehaviour 分别推进同一个 Session 的 simulation 时间。

旧 `StageTimer` 的独立场景兼容方式是持有自己的 `SessionTimerService`，由自身每帧显式推进；一旦它接入 `LevelSessionHost.Session.Timers`，不得再自行调用该共享 Timer 的 `Tick`。

## 3. 通用模块与 Adapter

### 3.1 火焰

`HMP_game/Assets/GameModules/Fire/` 提供 `FireState`、`IFireCapability` 和不依赖 Unity 的 `FireStateModel`。`IFireCapability` 提供 `TrySetState`、`TrySetFrozen` 与 `TrySetVisualParameters`；每个火源各有一个模型，不能由关卡流程直接写粒子状态。

`FireCapabilityAdapter` 将 `FireEffectController` 映射为实体能力，`FireSuppression` 作为对应模型的唯一压制 Tick 驱动。`FireEffectController.sessionHost` 会读取 Simulation 控制权，以便暂停时冻结火焰模型和当前表现。`ExtinguisherSpray.ConfigureTargets(FireSuppression legacyTarget, FireSuppression[] targets)` 必须由场景安装器显式提供候选火源，不能回退为全场景搜索。

### 3.2 交互、门、拾取和座椅

`HMP_game/Assets/GameModules/Interaction/` 定义：

- `IInteractionCapability`：读取提示并提交一次交互请求。
- `IDoorCapability`：`TrySetOpen`。
- `IPickupCapability`：读取持握状态并 `TryDrop`。
- `ISeatCapability`：读取占用/过渡状态并 `TryLeave`。
- `InteractionRequestGate`：按请求 ID 去重、完成或取消，防止键盘与 UI 对同一交互重复执行。

`LegacyInteractionCapability` 是受控兼容层：它持有显式 `IInteractable` 和 `EntityInteractionSource`，不靠 `FindAnyObjectByType` 找对象。`DoorCapabilityAdapter`、`PickupCapabilityAdapter`、`SeatCapabilityAdapter` 分别包装现有 `DoorController`、`PickupItem`、`SeatController`；现有 Unity 脚本仍是动画、持握和坐姿表现的状态所有者。

`EntityInteractionBridge` 是非办公室专用的场景桥。它通过 `Configure(EntityScopeHost, GameEntity, Interactor, LevelSessionHost)` 接线；`TryInitialize` 安装 Scope 和 Session；`TryGetInteraction` 根据 `EntityHitProxy` 命中解析能力；`TryInteractRequest(target, requestId, out error)` 用请求 ID 去重并在 Interaction 控制权被占用时拒绝。受 Scope 管理的 Collider 在停止后仍被视为受管，避免 Interactor 回退到旧 `IInteractable` 路径。

### 3.3 题目、计分、表现和可见性

以下模块已经具备通用模型或接口，后续关卡按需装配：

| 路径 | 用途 |
|---|---|
| `GameModules/Assessment/QuestionSession.cs` | 以 attemptId 管理答案、超时和取消的终态竞争，只产生一个结果。 |
| `GameModules/Score/ScoreLedger.cs` | 以 businessKey 幂等写入一次计分记录。 |
| `GameModules/Presentation/SessionPresentationGate.cs` | 弹窗/讲解领取 Session 控制租约，保存并恢复 HUD 与光标。 |
| `GameModules/Visibility/IVisibilityCapability.cs` 与 `VisibilityCapabilityAdapter.cs` | 可见组状态的通用能力入口。 |
| `EntityGuidanceService.cs` | 实体锚点驱动的路径/指引适配入口。 |

这些模块不要求每关全部存在。无题目、无门、无座位或无讲解的关卡只声明自身必需的实体、角色绑定和能力；验证器不应因为 Office 专属对象缺失而阻止该关启动。

## 4. LevelDefinition 与导航

`HMP_game/Assets/GameContent/Common/EntityAdapters/LevelDefinition.cs` 是明确的场景内容入口。它需要 `levelId` 与 `scenePath`；`runLegacyStages = false` 表示本关不加载旧 JSON 阶段配置，也不启动 `LevelFlowRunner` 的旧流程。`LevelBootstrapper.definition` 引用该资产，且通过 `entityBindings.TryInitialize(Entry.id, ...)` 启动实体会话。

`HMP_game/Assets/GameContent/Common/AppNavigationService.cs` 是单场景加载的统一网关：

1. `AppNavigationService.Instance.TryLoadSingle(scenePath, out operation, out error)` 建立请求。
2. 调用 `operation.AllowActivation()` 允许实际激活；可用来等待 CG 或加载界面。
3. 仅 `NavigationOperation.IsCancellable` 为 true 时可 `TryCancel()`。

Unity 已建立原生 `AsyncOperation` 后，`NativeLoadStarted` 会置位，操作即不可取消；`TryCancel()` 返回 false。调用方必须等待该加载完成或失败，不能把已开始的原生加载当成已取消，也不能并发开启第二个单场景切换。

## 5. 第三场景通用模块试点

试点源场景是 `Assets/Scenes/第三场景.unity`，安装结果只写入 `Assets/Scenes/第三场景-通用模块试点.unity`。不要直接对源场景运行试点安装器。

安装器为 `HMP_game/Assets/Editor/SharedModuleSetup.cs`：

1. 在 Unity 菜单选择 **Tools / Shared Modules / Create Third-Scene Pilot and Install**，或在批处理执行 `SharedModuleSetup.InstallThirdScenePilotBatch()`。
2. 若副本不存在，工具使用 `AssetDatabase.CopyAsset` 创建副本；随后只打开、装配和保存该副本。
3. 工具为玩家创建 `player.main`，为出生点创建 `anchor.player.spawn`；建立 `EntityScopeHost`、`SceneBindingSet`、`LevelSessionHost` 和 `EntityInteractionBridge`。
4. 现有 `DoorController`、`PickupItem` 以及试点专用的 Seat 各自获得实体、对应 Adapter 和一个显式 `EntityHitProxy`。原第三场景没有已部署的 `SeatController`，安装器仅在试点中创建可见的 `Shared Module Test Seat`（座面、靠背、`SeatController` 和 `Seat Anchor`），并登记 `anchor.seat.third.test`；源场景不新增该测试物。安装器维护已声明 Collider 集，避免同一 Collider 被两个 Proxy 注册。
5. 源火创建 `fire.third.a`；复制源火实例创建 `fire.third.b`。两个对象各自拥有 `FireEffectController`、`FireSuppression`、`FireCapabilityAdapter` 和 origin 锚点；安装时清空两者的 `followTarget`，关闭火焰 F9 调试，避免复制后两火跟随同一物体而重合。喷射器用 `ConfigureTargets(first, new[] { first, second })` 明确接线。
6. 原第三场景保留的 `LevelFlowRunner` 与 `StageTimer` 在试点副本中禁用；`LevelBootstrapper` 改用 definition 且 auto start，使旧阶段流程不再抢火焰、计时和输入。
7. 工具创建或更新两个指向同一试点场景的 Definition：`third_scene_shared_modules_a` 与 `third_scene_shared_modules_b`。两者 `levelId` 不同，均 `runLegacyStages = false`。A 的初始双火为 Small/Medium，B 为 Large/SmokeOnly；`initialFires` 按实体 ID 配置初始状态，普通 Play 启动即可看到火源，无需通过测试代码点火。未声明 initialFires 的关卡不要求火源模块。

复制的源场景若残留 Office/Quiz 专有组件，安装器会只在试点中移除 `OfficeFireChoiceFlow`、`OfficeEntityBindings`、`OfficeChoiceTarget`、`OfficeChoiceInteraction` 和相关的 SceneChoice、Quiz、Instructor 视图组件。验证错误会列出残留组件的类型与所在 GameObject，便于修正源场景遗留；不会写回源场景。

为防止旧初始化器覆盖试点绑定，`Assets/Editor/FireSetup.cs`、`InteractionSetup.cs` 和 `GuidanceSetup.cs` 的自动 `Run()` 现只匹配 `Assets/Scenes/办公室场景.unity` 与 `Assets/Scenes/第三场景.unity` 两个原始场景路径。打开 `第三场景-通用模块试点.unity` 时它们会跳过；不得对试点副本强制运行这些旧 Setup。

安装器会在保存前检查：无 Office 专用运行组件、双 FireSuppression 完整、两个 Definition ID 不重复、Scope Host 与 Bridge 存在，以及 `EntityScopeHost.Validate` 无错误。检查失败时应先修显式引用或 Collider，不能用全局搜索绕过。

## 6. 办公室关卡的保留边界

办公室仍使用 `OfficeEntityBindings`、`OfficeChoiceCapabilityAdapter`、`OfficeFireChoiceFlow`、题库、反馈和讲解视图。这些类承载“三题、到指定物体执行、讲解顺序、办公室文案和结算皮肤”等内容规则，不能被迁到通用的 Door/Pickup/Seat/Fire 模块里。

办公室实体试点的安装与检查入口保留在：

- `Assets/Editor/EntitySetup.cs`：**Tools / Entity System / Create Office Pilot and Install**、**Install Current Office Pilot**，以及 `EntitySetup.InstallOfficePilotBatch()`。
- `Assets/Editor/EntityIntegrationChecks.cs`：**Tools / Entity System / Check Office Pilot Baseline**，以及 `EntityIntegrationChecks.BeginBatch()`。

新增关卡优先选择 `EntityInteractionBridge + LevelDefinition`；只有确实需要办公室三题流程时才引用 `OfficeEntityBindings`。这样不会让新关卡被四选一、三题或教官 UI 固定住。

消防参数可选用 `FireProfile` 资产，由 `FireSuppression` 只读提取参数；压制进度、复燃和熄灭确认只保存在每个火源独立的 `FireStateModel`。一个喷射器的有效预算在命中的火源之间均分；不同喷射器对同一火源取最大覆盖率，不隐式叠加加速。候选采样按显式列表顺序和预算上限执行，复用采样缓冲区。

导航除 `TryLoadSingle` 外，还提供 `TryLoadDefinition(definition, out operation, out error)`；目标 `LevelBootstrapper` 在 Awake 消费本次导航的 Definition，避免仅按 Scene 名反查关卡。原生加载启动前可取消，启动后 `TryCancel` 返回 false；不会遗弃一个 `allowSceneActivation = false` 的原生操作而堵塞 Unity 加载队列。

`QuizTimerHUD` 已实际使用 `QuestionSession`，通过同一时钟竞争答案和超时；`LevelFlowRunner` 用 attemptId 写入 `ScoreBoard.RecordAttempt`。反馈、讲解和结算实际接入 `SessionPresentationGate`，多方暂停互不抢占。结算通过 `SettlementPresentationConfig` 自定义品牌/教官资源，题目按九题分页；讲解按完整 line/video 数组逐步执行，保留旧题库格式。

## 9. 使用入口与边界

- 可直接打开 `HMP_game/Assets/Scenes/第三场景-通用模块试点.unity` 并 Play，体验通用交互和双火源；对应配置在 `Assets/GameContent/LevelDefinitions/`。这是验证场景，不自动加入正式选关列表或 Build Settings。
- 办公室继续使用 `办公室场景-实体试点.unity`。正式办公室流程仍保留兼容路径；本轮没有把正式场景直接替换成试点。
- 新场景按需装配实体、能力与 Session；无需添加题库、教官或办公室流程。当前 Definition 是内容入口，模块存在性由显式场景组件和引用决定，尚未实现独立的模块依赖拓扑清单及循环依赖诊断面板。
- 门/座椅/持握/手部表现继续使用原 Unity 后端；能力接口统一访问并负责退出清理。交互 requestId 的完成表示命令已被受理，座位动画完成应继续观察 `IsTransitioning`/`IsOccupied`，不把同步返回值当成动画完成。
- 可见组能力与实体指引入口已提供；并未批量重写全部旧场景的天花板、相机、手部引用和 UI。正式内容迁移需逐场景装配与视觉确认。
- 现有自动验收没有替代目标设备画面、手部握姿/碰撞手感和帧耗时/GC 基线测量。隔离 Editor 的日志中仍有既有过时 API 警告、Unity SearchDatabase 异常和服务网络超时；测试与项目编译已分别核对，不能将整份 Editor 日志称为零错误日志。
