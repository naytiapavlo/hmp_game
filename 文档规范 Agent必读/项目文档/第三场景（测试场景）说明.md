## 二、调试热键 F8 / F9（为什么第三场景曾经按了没反应）

两个键都是**组件级调试热键**，用新输入系统的 `Keyboard.current` 读键，不需要在 Input Actions 里配置、也不存在「全局」开关；
**谁挂在场景里、谁被启用，才有反应**。这也是第三场景一开始失效的原因：

| 键 | 归属组件 | 办公室场景 | 第三场景（修复前） | 修复 |
|---|---|---|---|---|
| **F8** | `GuidanceSystem.debugMode` → 准星指向的地面点生成指引路线 | 有 `路线指引` 根 → 可用 | 我精简时把 `路线指引` 整个删了 → 无组件 → 按了没反应 | 工具不再删该根；**缺失时自动从办公室场景复制回来** |

> → 按下面的独占规则，**F9 仍归火源**，`LevelFlowRunner` 自动让出。另新增 **F10**＝跳过当前阶段（第二关只有一段 freeRoam，

### F9 独占规则（2026-09-21 修复"随机切换"）

**症状**：连按 F9，火势会变但顺序不是 `None→SmokeOnly→Small→Medium→Large`，像随机跳级。

**原因**：`FireEffectController.Update()` 与 `LevelFlowRunner.Update()` **各自**都读 F9。当两者同时生效时
（本场景 `FireEffectController.debugMode=1`，而关卡流程又在跑 → `LevelFlowRunner.Config != null`），
一次按键被推进**两档**：None→SmokeOnly→Small、Small→Medium→Large、Large→None→SmokeOnly，
所以永远看不到完整的五档循环。Console 里的指纹是**每个按键产生 3 行日志**：

```text
[Fire] 火势分级 → SmokeOnly          ← LevelFlowRunner.CycleFireLevel() 调的 SetLevel
[LevelFlow] [验收] 手动火势分级 → SmokeOnly   ← CycleFireLevel 自己的日志
[Fire] 火势分级 → Small              ← 同一帧 FireEffectController 自己的 F9 又推进一档
```

**修复**：定一条独占规则——**火源自己开着 `debugMode` 就由它独占 F9**：

- `FireEffectController` 新增只读属性 `DebugKeyEnabled => debugMode`；
- `LevelFlowRunner.Update()` 改为 `if (f9Key.wasPressedThisFrame && (fire == null || !fire.DebugKeyEnabled)) CycleFireLevel();`
  —— 只让出 F9，F8（冻结）/F10（跳段）不受影响；
- `FireEffectController` 的 F9 另加 0.2s 节流，防同一次按键被连续多帧观测到（`wasPressedThisFrame` 按输入更新判定）而跳档。

于是：第三场景 `debugMode=1` → 火源独占 F9（单档循环）；办公室场景 `debugMode=0` → 仍由 `LevelFlowRunner` 独占。

**注意（2026-09-22 起已不适用，保留作历史）**：本场景的 `LevelBootstrapper.autoStart` 若被勾上，关卡流程会在这个场景里跑、
火势会被 cue 按阶段自己改。当时它还没登记关卡、只当交互测试场景用，所以建议保持关闭；
**现在它就是第二关**，`autoStart=true` 是正常状态（阶段开始时按 `fireCue` 改火势，F9 仍归火源，两者不冲突）。


## 三、火源摆位规则

按需求「火源不要放桌上，放旁边地面」：

1. 做旧插排落在 `SM_Desk_01` 旁边的地面：在桌子前/后/左/右四个方向各取 0.5m 外侧点，
   取第一个不与其它渲染体包围盒重叠的点（**插排自身不算障碍**，否则重跑会把火源挪到别的方向）；四个方向都被占时退回 +X 方向；
2. 用插排自身包围盒把**底面精确压到地面**（地面高度取工位桌底面 y）；
3. `起火点` 贴插排顶面 +0.02m，并接线 `FireEffectController.followTarget = 插排`（挪插排火自动跟随）。

地面高度取「桌子底面 y」而不是 `floor` 立方体顶面，是因为工位桌本来就站在楼面上，这样两者永远一致。

### 抱起动作朝向（2026-09-21 调整）

- **旧行为**：`ArmsPitchFollow.TrackAnchorsToHands()` 每帧把持物锚点的旋转写成「仅偏航」（`= body.rotation`），
  物品挂在锚点下 → **在世界坐标里始终直立**。低头看手中的长条物时物品不随视线前倾，
  相机 0.3m 近裁面会切进物品、看到内部。
- **现行为**：`PickupItem.holdAlignsToView = true`（默认）→ 物品朝向跟随**摄像机视角**
  （俯仰只作用在相机自身），相对画面始终朝上；**位置仍然跟手**（锚点由 ArmsPitchFollow 每帧贴合掌心）。
- **实现（层级解析，不写世界位姿）**：

  ```text
  Anchor（ArmsPitchFollow 每帧贴手掌，旋转只含 yaw）
    └─ HoldPose（PickupItem 创建：局部旋转 = 俯仰 → 世界朝向 = 视角朝向）
         └─ 物品（localPosition = holdPositionOffset，localRotation = holdRotationOffset）
  ```

  位置零帧延迟（层级在渲染时解析）；`HoldPose` 的局部旋转**只含俯仰、不含 yaw**，
  所以与"父级 yaw 何时更新"无关。
- **两次踩坑记录**：
  1. *浮空*：偏移算在锚点帧（只含偏航）、朝向算在视角帧，两者一旦有俯仰就错开——
     物品中心与手的距离 = `|偏移| × 2·sin(俯仰/2)`，低头 60° 就飘 0.25m。现在偏移与朝向同在
     `HoldPose` 帧里，结构上不可能不一致。
  2. *快速转身抽动*：早期版本每帧写物品的**世界旋转**（含 yaw），与父级 yaw 的更新先后差一个 ΔYaw，
     误差 ∝ 转身速度 → 快速左右转会"鬼畜抽动"。现在只写 `HoldPose` 的**局部**旋转（不含 yaw），
     根本上免疫该时序问题。
- **持握点**：模型原点在底部中心。v1 用"包围盒中心 + 身前推 0.12m"（`(0, -center.y, +0.12)`）避免瓶身顶到脸；
  v2 起改为**扶手式**——抓握点落在**提把与压把的几何中点**上：
  `holdPositionOffset = −(holdRotationOffset 旋转 × (抓握点局部坐标 × 物品缩放))`，位置不再由人估。
  **必须用渲染包围盒求部件位置，不能用节点 transform**（见下节踩坑）。
- **坐标系必须一致（2026-09-21 二次修）**：位置偏移必须与朝向用**同一个坐标系**——
  现在两者都挂在 `HoldPose` 下，结构上保证一致；物品中心恒定落在手上，上下看都不飘。
- **逐件指定，默认关**（`InteractionSetup.PickupConfigs` 的 `AlignsToView` 列）：

  | 道具 | 模式 | 视角对齐 | 理由 |
  |---|---|---|---|
  | `SM_Extinguisher_01` | **扶手式**（`HandleAndNozzle`） | **开 + 俯仰与手臂同幅** | 长条物：低头不会把瓶身翻过来露内部；两点持握（右拳提把 + 左掌握喷头）必须与手臂严格同幅，见下 |
  | `SM_Keyboard_01`（临时测试物） | 双手 | 开 | 同上 |
  | `SM_Cup_01` | 单手 | **关**（世界直立） | 模型原点在底部、抓握点在**掌心凹槽**里，几何从支点向上 0.21m；跟视角俯仰会让它落进手部网格/近裁面 → 看起来"消失"（2026-09-21 实测踩过） |

  想改用哪个就在这张表里翻开关；`PickupItem` 里也留有同名序列化字段可逐件微调。

  **持握位置偏移**也在同一张表里可选指定（`null` = 保持现值、不覆盖）：
  - `SM_Cup_01` = `(0, +0.03, 0)`：把杯身相对手部**抬高 3cm**，减少杯底与手指/掌心的穿模
    （水杯是世界直立模式，所以 Y 轴就是竖直方向）；
  - `SM_Extinguisher_01` = `null`：它由 `ExtinguisherSetup` 独占写入（提把反推 + 扶手式模式），
    在表里覆盖会打回双手模式。

  **持握字段的单一归属（2026-09-22 修，重要）**：`InteractionSetup.PickupConfigs` 里的条目可以带
  `ownsHoldPose: false`——只登记名字（让 `CleanupStalePickups` 认得它、不把组件剥掉），
  **一个持握字段都不写**。灭火器条目就是这个值。
  起因：`InteractionSetup` 会无条件写 `carryMode` / `holdRotationOffset`，把灭火器从 `HandleAndNozzle`
  打回 `TwoHands`、并清掉解出来的朝向偏移；而两个 `[InitializeOnLoad]` 工具的执行顺序**没有保证**，
  "谁后跑谁生效"等于随机结果。现在每个持握字段只有一个写入者。

- **丢出时双方被弹开（2026-09-21 修）**：`Drop` 原来**先恢复碰撞、而物品仍在胸前/掌心位置**——
  持握点决定了碰撞盒跨"手 ± 半高"，与玩家胶囊体重叠，PhysX 解穿插时把**物品和玩家一起弹开**
  （灭火器 0.5m 高几乎必然重叠、水杯偶尔，所以表现为"有概率"）。现在释放顺序改成：
  ① 按「玩家胶囊半径 + 物品半径 + 0.05m」沿身前水平把物品**推出身体** → ② 再恢复碰撞与物理 →
  ③ 额外**短暂忽略 0.4s「物品 × 玩家所有碰撞体」的碰撞对**，作为贴墙等推不足时的兜底
  （0.4s 后自动恢复，玩家之后仍能正常踢到地上的物品）。

### 现实持握动作：右拳提把 + 左掌握喷头（2026-09-22 改）

要求（用户原话）：**拿取灭火器后，动作改为符合现实的灭火器使用动作——右手握住 2 个红色手柄，左手握住喷头。**

沿用项目既有的「程序化 FK 姿态 + 掌面锚点贴合」架构，**不引入 IK**（手部资产没有动画 clip、没有 Animator）。

| 环节 | 实现 |
|---|---|
| 持握模式 | `PickupItem.CarryMode.HandleAndNozzle`（枚举**尾部追加**——序列化按索引存，插入会错位） |
| 吸附锚点 | 右手锚点 `Anchor_RHand`（`Take()` 里只有 `TwoHands` 才用胸前 `Anchor_Carry`），瓶子**拎在右拳**里 |
| 手部姿态 | `HandPoseController.Pose.Extinguisher`——**左右完全不对称**（`OffsetExtinguisher` 按侧取表，不做镜像）：右手四指卷握提把横梁 + 拇指搭压把；左手前伸内收、卷握喇叭口 |
| 持握点 | 提把 `CarryHandle` 与压把 `SqueezeLever` 的**几何中点**（渲染包围盒，不是节点 transform），取反即偏移 |
| 提示文案 | `interactPromptOverride = "E 拿起灭火器"`（`PickupItem` 新增的可选覆盖字段，避免在通用组件里硬编码道具名） |

**踩坑（2026-09-22 实测，一定要记住）：语义部件的 transform 全在原点，几何烘在网格里。**

- 该模型的部件节点 transform 都在 `(0,0,0)`：`CarryHandle` 节点局部坐标 = `(0,0,0)`，
  而提把**网格**实际在局部 `(0, 0.418, -0.079)`。
- 于是"按节点 transform 反推持握点"算出 `holdPositionOffset = (0,0,0)` →
  瓶身原点（瓶底）落在手腕上、整瓶向上穿过脸，**手臂整个被吞进瓶身网格里看不见**（用户实测报障）。
- 修法：一律经 `Assets/scripts/交互/PropGeometry.cs` 按**渲染包围盒**取几何中心（空挂点无渲染体时才退回 transform），
  并加防呆——抓握点落在瓶底下方 1/4 高度内一律判为不可信、改用包围盒中心兜底。
  改造后 `ExtinguisherSetup` 报告里会打印解析出的抓握点与两点距离，可直接核对。

### 喷射与火焰压制（2026-09-21 新增，`ExtinguisherSpraySetup` 部署）

工具：`Assets/Editor/ExtinguisherSpraySetup.cs`（`InitializeOnLoad` + `Library/ExtinguisherSpraySetup.v4.done`
标记 + 菜单 `Tools/Props/部署灭火器喷射（粒子 + 压制接线）` 强制重跑 + 报告 `Library/ExtinguisherSpraySetup.txt`）。
注意本工具**只管喷射**：粒子资产 + `ExtinguisherSpray`/`FireSuppression` 接线，
持握字段一个都不碰（归属见上节"持握字段的单一归属"）。

| 产物 | 说明 |
|---|---|
| `Assets/VFX/T_SprayParticle.png` | 128×128 程序生成径向渐变白雾贴图（零外部素材，无版权风险） |
| `Assets/VFX/MAT_ExtinguisherSpray.mat` | 复用 `HMProtection/ParticleFx` 着色器（透明混合），米白偏黄 = ABC 干粉 |
| `Assets/VFX/VFX_ExtinguisherSpray.prefab` | 锥形干粉雾：Cone 9°、220 粒/秒、6–8 m/s、世界空间模拟、粒径 0.09→0.55 膨胀、≤480 粒子（v3 加重） |

| `起火点` 上挂 `FireSuppression` | 压制状态机（渐变/降级/复燃/扑灭确认） |

**操作**：E 拿起灭火器（右拳提把 + 左掌握喷头）→ **按住鼠标左键**喷射（松开渐停，粉雾自然飘散）。
持握约束每帧自动更新，不需要按 F11。

**判定规则**（表现与判定分离——粒子纯表现，判定是相机射线对火焰根部带的解析求交，不用物理）：

- 有效：视线覆盖火焰**根部带**（火源顶面上方 0.35m、半径 0.5m）且喷嘴距火源 ≤3m；
- **只喷火苗上部无效**（Console 节流提示「无效命中」）——计划书 §4.3 硬规则；
- 有效喷射 → 火苗发射率渐小（`FireVfx.SetIntensity`，级内渐变不是硬切）→ 压到阈值降一级
  （Large→Medium→Small→SmokeOnly→None）；SmokeOnly 级压烟量，压到阈值熄灭；
- 停手 → 级内缓慢恢复（余火回旺）；**曾被压降级又停手 ~4s → 余火复燃 Small→Medium（一次一级）**；
- 到 None 后 **5s 观察窗**无复燃才触发 `Extinguished` 事件（第二关「扑灭且观察 5 秒」计分接口）；
- **F9 互锁**：`FireSuppression` 每帧比对火级别，发现外部切换（F9/将来关卡 cue）就重置状态继续工作，
  `FireEffectController` 本体零改动。

**第二关预留接口**：`ExtinguisherSpray.PinPulled/PullPin()`（拔销步骤）、
`SpraySecondsTotal / SweepAngleTotal`（喷射时长/水平扫角累计——「扫射 10 分」数据）、
`FireSuppression.LevelLowered / Reignited / Extinguished` 事件（计分与结果表现接这里）。

**自动验收**：菜单 `Tools/Props/验收：灭火器压制链路`（`ExtinguisherSprayChecks`，进 Play 直接驱动
`ApplySpray` 断言降级链/外部自愈/喷上部无效/复燃，报告写 `Library/ExtinguisherSprayChecks.txt`）。
喷射的手感与射线部分按下节手动验收。

**手动验收步骤**（进第三场景 Play）：

1. F9 把火调到 Small 或 Medium；
2. 走到灭火器旁，E 双手抱起；对准插排**根部**按住左键：粉雾锥形喷出，火苗 ~1s 渐小后降级，
   到冒烟级后烟渐弱直至熄灭；Console 依次出现 `[FireSupp] 压制降级 → …` 与 `扑灭确认`；
3. 中途松开左键几秒再喷：火苗回旺；若已压降级，停手 ~4s 出现 `复燃：余火回升 Small → Medium`；
4. 只把准星抬到火苗**上部**喷：火无变化，Console 提示「无效命中：只喷到火苗上部」；
5. 站 3m 外喷：Console 提示「超出有效射程」；
6. 放下灭火器（E/Q）后按左键：无反应；
7. **反馈检查**：抱起时底部提示「按住左键喷射」；喷中根部时准星变淡蓝白并放大；只喷上部/超程时
   底部提示切换为「对准火焰根部才有效」/「太远了——靠近些再喷」；松开左键回到「按住左键喷射」；
   放下灭火器后提示恢复为基础交互提示（「E 放下 · Q 丢弃」等）。反馈走 `InteractionHUD` 的
   覆盖通道（`SetPromptOverride`/`SetCrosshairTint`），不与 Interactor 的每帧提示打架。
