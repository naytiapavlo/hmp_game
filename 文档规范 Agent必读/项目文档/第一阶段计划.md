> 总体任务：参考 `ui/demo界面/` 完成**初始界面**与**第一关卡**。

## 一、本阶段总目标

一条**可完整走通、可演示**的主线：

```text
初始界面（主菜单）
  → 选择场景
  → 第一关卡：[失火原因动画] → [选择题（俯视）] → [第一人称自由移动 + 取物指引]
             → [结果动画] → [科普视频] → [结算返回主菜单]
```

第一关内容按计划书设定：**初起火灾应对**（起火原因：办公区插排过载 / 串接插排，场景内已有对应道具模型）。

## 二、第一关卡状态机（唯一权威流程）

```text
Boot → MainMenu → SceneSelect → Level1_Load
  → L1_IgnitionCutscene    失火原因动画（默认 6 秒，不计时，可重播）
  → L1_Quiz                俯视视角 + 隐藏天花板 + 隐藏人物，每题 15 秒
  → L1_TransitionBack      切回第一人称（过渡动画，二期补）
  → L1_FreeRoam            自由移动 + 人物指引取物，倒计时（时长待定，建议 45–60 秒）
  → L1_ResultCutscene      播放"选择结果"动画（正确 / 错误两种）
  → L1_ScienceVideo        科普视频（电视屏 + 角色解说面板）
  → L1_Settlement          本关结果与得分 → 返回主菜单
```

规则（沿用计划书）：

- 只有**答题与操作段**计时；动画、解说、暂停、等待「继续」期间计时与火焰模拟全部冻结。
- 超时**也要**出结果与解说，不跳过、不中断培训。
- 第一关 4 题、每题 7.5 分、共 30 分，**至少 3 题正确**才算通过。
- 第一关不通过**不阻断**后续关卡（本阶段只做第一关，接口先留好）。

- 场景切换用 SceneManager 单场景加载 + 加载进度表现（本阶段仅一个场景，接口按多场景预留）。
- 暂停菜单（ESC）：继续 / 重开 / 返回主菜单。

## 四、任务 2：交互逻辑

统一实现一套 `Interactable` 交互框架（准星 + 射线检测 + 提示条），现有 `Assets/scripts/人物/body.cs` 第一人称控制器**在其基础上扩展，不重写**。

| 功能 | 实现要点 | 验收 |
|---|---|---|
| 拿起物品 | `IInteractable` + 射线 2–3 m；拿起后吸附到第一人称双手（复用 `Assets/FPHands/FPHands_01.prefab`），可放下/丢弃；重物（灭火器）与轻物分别设定持握姿态 | 准星对准显示提示，E 键拿起/放下，物品跟随不穿模 |
| 开门 | 门轴绕 Y 轴开合（可选推门/自动门），开合有插值动画与音效挂点；门后区域碰撞与视线正常 | 交互一次开、再交互关，动画平滑、无抖动 |
| 坐下椅子 | 交互后摄像机插值到坐姿锚点、锁定移动、切换视角限位；起身恢复 | 坐/起流畅，坐姿期间不能穿墙移动 |
| 通用交互反馈 | 可交互物高亮（描边或材质提亮）、提示文案、不可用状态提示 | 三类交互都有明确视觉提示 |

技术要点：

- Input System 的 `Player` Action Map 增加 `Interact`（E）、`Drop`（Q）、`Cancel`（ESC）。
- 物品用 `Rigidbody` + 拿起时 `isKinematic`，放下恢复；避免与 `CharacterController` 冲突。
- 交互对象用 Layer（`Interactable`）过滤射线，避免打到天花板、玻璃与玩家胶囊。

## 五、任务 3：第一关卡

### 5.1 失火原因动画（进入关卡先播）

- 内容：办公区插排过载 / 串接插排 → 冒烟 → 起火，明确展示"为什么会烧起来"。
- 形式：Timeline（`com.unity.timeline` 已在依赖中）播放固定机位镜头 + 火焰/烟雾特效；默认 6 秒，**不计时**，可重播。
- 相机：解锁玩家控制，切演示相机，播完切回第一人称。

### 5.2 选择题阶段（俯视）

参考 `ui/demo界面/a3526715-…png`：俯视全屋、天花板已隐藏、起火点可视化、红色标签气泡指向具体位置、顶部火焰进度条。

- **视角切换**：启用独立俯视相机（正交/高位透视），禁用玩家相机与输入；过渡动画（推拉/淡入）**二期再加，一期硬切或简单 Lerp 即可**。
- **隐藏天花板与人物**：直接复用现有 `CeilingVisibility`（天花板总开关）与人物根物体上的 `VisibilityToggle`，由关卡状态机在进入选择题时下发隐藏、返回时恢复——不要再写一套。
- **题目**：第一关 4 题固定顺序（报警示警 / 识别带电火灾 Class C / 由获授权人员安全断电 / 判断是否具备初期扑救条件），每题 15 秒，超时按未作答处理并照常出解说。
- **题面 UI**：选项为红色胶囊按钮（`ui/关卡/选择题.png`）排列于屏幕下方；顶部进度条 + 火焰图标表示剩余时间；选中态高亮。
- 每题作答后 → 解说 + 正确答案 + 用户答案（默认 6 秒，可重播）→ **等待点击「继续」**，不自动推进。

### 5.3 返回第一人称 + 人物指引取物

- 视角切回第一人称，恢复玩家移动与交互；天花板、人物恢复显示。
- 按玩家在选择题中的选择给出**取物指引**：红色标签气泡 + 地面指引箭头指向目标物品（示例映射，具体题面待定）：

| 玩家选择 | 指引目标（场景内已有资产） |
|---|---|
| 使用灭火器 | 走廊/墙边灭火器箱 |
| 用水扑救 | 饮水机 / 水桶（`SM_WaterDispenser_01`） |
| 断电处置 | 配电箱 / 起火插排所在工位 |
| 报警示警 | 电话 / 门口报警点 |

- 计时：进入本段开始倒计时（建议 45–60 秒，**最终时长待确认**），顶部进度条 + 火焰图标持续显示；超时或完成行为都进入下一段。
- 玩家拿到目标物品 / 完成动作 → 判定成功；超时未完成 → 判定未完成（不阻断流程）。

### 5.4 结果动画

- 播放玩家选择的**结果演示**：正确 → 规范处置演示；错误 → 火势扩大 / 处置失败的演示（参考 demo 中红色大字的结果表现）。
- 默认 6 秒，可重播；随后展示"正确答案 + 用户答案"。

### 5.5 科普视频阶段

参考 `ui/demo界面/0cd43a47-…png`：

- 左侧电视屏（`ui/关卡/科普视频电视.png` 或场景内电视模型）用 **VideoPlayer + RenderTexture** 播放科普短片；
- 右侧角色立绘 + 底部带"角色名"标签的解说面板（角色素材由 Astra 提供）；
- 可跳过 / 可重播；播完进入结算。
- **视频文件与角色立绘尚未提供** → 先用占位素材跑通链路。

### 5.6 结算

按计划书：显示本关得分（0–100 制，60 达标）、每题答题记录、通过/未通过，保存本地报告（JSON 或 PlayerPrefs），提供「返回主菜单」与「重玩本关」。

## 七、验收标准

1. 从主菜单可以进入选择场景 → 第一关 → 完整走完到结算 → 返回主菜单，全程无卡死、无控制权丢失。
2. 主界面 / 玩法说明 / 设置 / 选择场景四个界面均可正常打开、关闭、点击反馈正确，设置可保存。
3. 拿起物品、开门、坐下椅子三项交互均可稳定复现，有提示与动画。
4. 第一关：失火原因动画 → 选择题（俯视、天花板与人物隐藏）→ 回第一人称 → 指引取物 → 结果动画 → 科普视频，顺序正确；计时只在答题与操作段推进。
5. 每题 15 秒超时、取物段超时都能正常继续，不阻断流程。

5. 科普视频是外链文件还是 StreamingAssets（影响打包方式）。
