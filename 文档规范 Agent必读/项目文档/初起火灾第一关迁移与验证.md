# 初起火灾第一关迁移与验证

## 迁移结果

初起火灾第一关的运行入口已迁入关卡包 `Assets/Levels/level_1_initial_fire/`。包内场景、Definition、Lua 入口和配置共同构成该关卡的入口：

- `Config/level.json` 启用 Lua，并声明 `script.config: "Config/flow.json"`。
- `Config/flow.json` 保存 11 个教学阶段及其题目、时序和火势提示数据。
- `Scripts/main.lua` 在运行时读取 `level.config`，取得流程所有权后按零基序号调用 `flow.stage`；上一阶段完成且流程未暂停时推进下一阶段，全部完成后调用 `flow.finish`。
- `legacy.enabled` 为 `false`，包内旧 Resources 阶段配置不再作为当前运行入口。
- 主菜单 `SceneSelectUI.officeDefinition` 指向第一关包的 Runtime Definition，通过 Definition 导航到包内场景。

Lua 在这里负责编排顺序和流程状态检查。C# `LevelFlowRunner` 仍复用既有逐阶段表现、题目呈现与判题、计分、教官提示和结算服务。这保留现有成熟表现与交互实现，同时把关卡顺序和数据从旧的全局阶段入口迁入关卡包。

## 资源边界

第一关包拥有场景副本、`level.json`、`flow.json`、Lua 入口、题库引用和 Runtime Definition。`Art/` 仍用于将来的第一关专属资源。

办公室环境、消防道具、火焰特效、材质、UI 和其他已有视觉资源继续以共享引用方式使用原位置资产；此次迁移没有复制共享模型、材质或贴图，也没有生成替代美术。`Config/shared-assets.json` 可用于查看包外依赖。若将关卡包迁往其他工程，必须同时迁移这些共享依赖。

## 流程所有权和故障处理

第一关 Lua client 调用 `flow.prepare` 后成为当前 session 的唯一流程拥有者。`flow.stage`、`flow.status` 和 `flow.finish` 只接受该 client 的调用；另一个 client 准备流程会收到 `flow_owned`，未拥有流程的调用会收到 `flow_not_owned`。

Lua 的 `stop` 调用 `api:dispose()`。VM 启动失败、运行异常、session 停止或场景释放同样会释放 client，并取消该 client 当前的 C# 流程。阶段逻辑出现 C# 错误时通过 `flow.status.error` 返回，Lua 将其视为失败，不继续推进后续阶段。

## 打开与维护

直接运行 `Assets/Scenes/初始界面.unity`，按原有“开始训练 → 办公室 → 开始”进入；也可直接打开包内 `Scenes/level_1_initial_fire.unity` 运行。调整阶段、火势或计分编辑 `Config/flow.json`，调整题目编辑 `Config/scene_choices.json`，调整编排编辑 `Scripts/main.lua`。之后执行 `Tools/Levels/Refresh Runtime Definitions` 和 `Tools/Levels/Validate Packages`。

包内旧 `Config/Resources/.../legacy.json` 保留为迁移对照，当前菜单和关卡包不读取它。原始办公室场景及其 Resources 配置也保留用于旧版回归，不再是正式菜单的第一关入口。

可通过 `Tools/Levels/Check Initial Fire Lua Migration` 运行完整验收，或在独立项目副本运行 `Unity.exe -batchmode -projectPath . -executeMethod OfficeLuaMigrationChecks.BeginBatch -logFile <日志文件>`。
